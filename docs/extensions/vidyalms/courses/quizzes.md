---
title: Build and deliver quizzes
description: Author questions, choose quiz settings, use banks and pools, and understand attempts and results.
---

Create a **Quiz** lesson from the course curriculum. Once saved, it opens an editor with **Questions**, **Selection rules**, **Quiz settings**, **Grading policies**, **Lesson details**, and **Access & release**.

## Write the first questions

1. Select **Add question** and choose a response format.
2. Write a clear prompt and the available responses or response instructions.
3. Mark the correct answer or configure manual grading, as appropriate.
4. Set points and useful feedback.
5. Preview the question as a learner and save.
6. Repeat, then arrange the questions in the intended order.

Use [question banks](question-banks.md) when the same material belongs in several quizzes. Questions authored directly in the quiz editor belong to that assessment; do not assume every change becomes a shared bank question.

## Set the assessment rules

In **Quiz settings**, review the instructions, passing percentage, attempt allowance, time limit, and learner feedback. Give learners the important rules before they start.

Where the installed policies support them, you can configure shuffle, presentation order, cooldowns, question-by-question delivery, and additional attempt behaviour. **Grading policies** controls how answers are marked. Only use policies you can explain to learners, especially partial credit or deductions for wrong answers.

A time limit belongs to the attempt. Closing a browser tab is not a reliable way to pause a timed quiz. Ask learners to check their connection and available time before beginning.

## Select questions deliberately

**Selection rules** can use fixed bank questions, conditions that draw questions automatically, and sections. For a random pool, make sure enough eligible, published questions match the filters to fill every requested place.

Preview several selections when possible. Two learners can receive different questions, but the intended difficulty and total assessment expectations should remain comparable.

## Explain what happens at submission

Automatically marked responses can receive results immediately. Written, uploaded, or other manually assessed responses wait for an instructor. A submitted attempt can therefore be awaiting grading rather than passed or failed.

Attempts keep the question version they started with. Editing a question later does not silently rewrite the historical attempt. Use the explicit [grading and regrading workflow](grading.md) when an assessment correction needs to affect recorded results.

The runner saves responses as the learner works and shows connection/save feedback. Learners should wait for submission confirmation. If connectivity fails, avoid starting duplicate attempts; check the existing attempt state first.

## Check completion and integrity settings

Connect the quiz to the course's completion policy when passing it is required. Review which feedback is visible during an attempt, after submission, and after grading.

Optional integrity signals, such as tab changes, are information for a human to review. They are not proof of cheating and should not replace accessible assessment design or a fair review process.

Test a pass, a fail, an exhausted attempt allowance, and a manually graded response before publishing an important assessment.
